# Changelog

All notable changes to this project are documented here. Algorithm version changes (see `docs/overworld-map-app-spec-v2.md` Section 4) are called out explicitly since they affect seed reproducibility.

## Unreleased

- M0: repo scaffold — frontend (Vite + React + TypeScript + Vitest) and backend (AWS SAM) packages created.
- M1: core types and pure functions — `types/map.ts`, `types/extensions.ts`, `core/rng.ts` (seeded RNG via seedrandom), `core/compass.ts` (8-direction math), `core/graph.ts` (BFS, connectivity, hop counts).
- M2: generator and validator — `core/generator.ts` (**ALGORITHM_VERSION 1.0.0**), `core/validator.ts` (all 7 invariants from spec Section 9), `core/names.ts`, and `core/prototypeMap.ts` (converts the 49-node `docs/overworld-map.html` dataset into a real `WorldMap` fixture, with several data-quality fixes — see `CLAUDE.md`'s "Notes on M2").
- M3: canvas rendering — `components/canvas/MapCanvas.tsx`, `NodeShape.tsx`, `EdgeLine.tsx`, `Tooltip.tsx`, and a minimal `store/mapStore.ts`. Renders the prototype map with pan (drag), zoom (wheel), and hover tooltips; visual styling follows spec Section 10b.
- M4: generation panel and seed system — `components/panels/GeneratePanel.tsx` (all sliders, seed + randomize, Generate, JSON download/import), `core/exporter.ts` (`toJSON`, `toMarkdown`, `toSVGString`), the full `store/mapStore.ts` action set (edit actions and undo/redo, ahead of M5's edit-panel UI), and `store/libraryStore.ts` (ahead of M6's Library panel). Same seed + params now reproduces an identical map end-to-end; JSON export round-trips through import.
- Spec update (pre-M4.5, no code yet): reworked the node/settlement/terrain classification system into a proper tiered model — new spec Section 3c, `NodeType` shrunk to `settlement | wilderness | poi`, `mountain`/`water` become a `BoundaryMarker` and a Wilderness-internal fork respectively, Settlement gains a civilian/outpost fork, and the generator's capability boundary is corrected (generator-capable through Tier 2 + boundary markers; only Tier 3+ detail and Factions stay permanently manual). Added milestones **M4.5** (taxonomy migration) and **M4.6** (generator capability expansion) to Section 16, both before M5.
- M4.5: taxonomy migration (**ALGORITHM_VERSION 2.0.0** — breaking data-model change) — `types/map.ts`/`types/extensions.ts` rewritten per spec Section 3c; `core/generator.ts`'s old mountain-edge placement becomes boundary-marker placement (`mountain_range` only for now — real reason variety is M4.6); `core/validator.ts`'s invariant 4 generalized to `boundary-placement`; `core/prototypeMap.ts` migrated (old `mountain`/`ruin` nodes become wilderness-with-boundary-marker / `poi`); `NodeShape.tsx`/`exporter.ts` updated for the new shape table and boundary badge glyphs. No new generation variety yet — see `CLAUDE.md`'s "Notes on M4.5" for the simplifications this enabled (exact-budget type placement replaced the old per-zone eligibility/force-fill machinery).
- M4.6: generator capability expansion (still **ALGORITHM_VERSION 2.0.0**) — `core/generator.ts` now assigns a real Tier 2 subtype to every node (biome/water feature, civilian scale/outpost kind, poi kind), places `coastal` and full boundary-reason variety (`coastline`/`mountain_range`/`canyon_void`/`magical_barrier`), can produce `sea_route` edges, and can optionally generate `TerrainZone` extension data (`generateTerrainZones` param). New shared `core/taxonomy.ts` module. `core/validator.ts` gained the extension invariants (`extension-node-ref`, `extension-edge-ref`, `faction-membership-unique`) for the first time, since extensions can finally be non-empty. `GeneratePanel.tsx` gained sliders/toggle for the new params. `extensions.factions` remains permanently generator-untouched. See `CLAUDE.md`'s "Notes on M4.6" for implementation decisions (weighted+capped civilian scale, the mountain_range-specific check-required fix, biome-based terrain-zone grouping).
- M4.7: visual layers and node shape/color revamp — `components/canvas/TerrainWash.tsx` (Layer 0) and `FactionTerritory.tsx` (Layer 1) now render in `MapCanvas.tsx`, backed by a new `components/toolbar/Toolbar.tsx` for layer toggling and a new `core/geometry.ts` (`convexHull`/`padHull`/`centroid`) shared with `exporter.ts`'s `toSVGString` so both rendering paths match. Node shapes/colors revamped per spec Section 10b: settlement is a yellow square (civilian) or diamond (outpost), wilderness is colored by its `Biome` subtype (land: plain circle; water: circle+ring), poi is a purple triangle for all four `PoiKind` values. `generateTerrainZonesStep` was fixed mid-milestone to cluster by spatial proximity rather than grouping every same-biome node map-wide — the original version produced unreadable, map-spanning overlapping washes, caught by rendering actual output to an image rather than by any test (a new regression test now guards against it). See `CLAUDE.md`'s "Notes on M4.7."
- M4.7.1: shareable map links — new spec Section 13b and `core/shareCode.ts` (`encodeParams`/`decodeParams`, `PARAMS_CODEC_VERSION`) pack a full `GenerationParams` (seed included) into a ~20-character base64url share code carried as the `map` query parameter. `store/mapStore.ts` updates the address bar via `history.replaceState` whenever `generate()`/`loadMap()` runs, and resolves the initial map with URL share code → localStorage → prototype-map precedence on load. `GeneratePanel.tsx` gained a "Copy Link" button. Verified end-to-end (not just the codec's own round-trip): a test regenerates the map from both the original and the decoded-then-re-encoded params and diffs the output. See `CLAUDE.md`'s "Notes on M4.7.1" for the encoding-precision reasoning (why five fraction fields are exact integer-percent but `nodeTypeBias` isn't) and the "hash" terminology correction.
- M4.7.2: macro region presets for biome coherence (**ALGORITHM_VERSION 2.1.0**, **PARAMS_CODEC_VERSION 2**) — `GenerationParams` gains `biomeMix` (six weights for the wilderness land branch); `core/generator.ts`'s biome pick changed from a flat uniform roll to a weighted pick against it, so a generated map reads as regionally coherent instead of scattering any of six biomes with equal odds. New `core/regionPresets.ts` defines six named presets (Temperate Mixed/Magical Forest/Frost/Arid Desert/Swampland/Tropical Jungle), each a `biomeMix` + water-fraction bundle — a UI/store convenience only, not a generator concept; the generator has zero preset awareness. `store/mapStore.ts`'s `rebalanceNodeTypeBias` generalized to `rebalanceShares` (now also driving six new biome sliders) plus new `applyRegionPreset`/`randomizeRegionPreset` actions; `DEFAULT_GENERATION_PARAMS` picks a random preset at module load, mirroring how `seed` already randomizes. `core/shareCode.ts` grew to codec v2 (20 bytes) with `decodeV1` updated (not left alone) to fill a sensible default for old links. `GeneratePanel.tsx` gained six biome sliders, a Region Preset dropdown, and a Randomize Region button. Verified visually via headless-Chrome screenshot (Frost preset renders as tundra-dominant with zero jungle). See `CLAUDE.md`'s "Notes on M4.7.2" for the "no new mode field" design decision and why a hard spatial-adjacency constraint was deliberately not built.
- Bug fix (**ALGORITHM_VERSION 2.1.1**): `repairConnectivity`'s component-merge strategy changed from size-ranked ("2nd-biggest component into biggest") to true nearest-component-pair (closest node pair across *any* two components). The old strategy had zero geographic awareness — a small isolated pocket sitting right next to other small pockets, but far from whatever the largest component happened to be, paid the full cross-map distance on its own turn instead of ever consolidating locally first. Found from a user-reported share-code URL whose map had a ~10.6-unit bridge edge (`River_crossing-1` → `Swamp-8`) when every other edge on it was under ~2 units; verified fixed on that exact case (longest edge afterward: 2.96 units) and pinned as a regression test. Deliberately scoped as a small, single-purpose, easily-`git revert`-able change touching only that one function. See `CLAUDE.md`'s dedicated notes section for the full trace.
- M4.7.3: grid sizing scaled to node count (**ALGORITHM_VERSION 2.1.2**, **PARAMS_CODEC_VERSION 3**) — found from a second user-reported bug (Delta-1/Ruin-3/Swamp-8: two neighbors at nearly the same true bearing from a third, so only one could claim the compass slot, and the loser fell back to a 45°-off label). The user considered three fixes and picked only one: give nodes more breathing room so tight local clusters are statistically rarer, without changing the direction-fallback logic itself (not a guaranteed fix for that exact case). New `core/geometry.ts`'s `recommendedGridDimensions(targetNodeCount)` sizes a square grid roughly double the linear dimension needed to fit the nodes (49 → 14×14, replacing the old fixed 10×8 default); `store/mapStore.ts`'s `applyRecommendedGridSize` action applies it explicitly (mirrors `applyRegionPreset`'s one-shot pattern, not a hidden slider coupling), exposed as an "Auto-size grid" button in `GeneratePanel.tsx` alongside widened Grid cols/rows slider bounds (6–20). `core/generator.ts`'s fixed `CANDIDATE_RADIUS` became a density-aware `candidateRadiusFor(params)`, calibrated to reproduce the old constant exactly at the pre-existing default density so only non-default grid/node combinations see different behavior. Widening the grid range past 15 broke `core/shareCode.ts`'s v1/v2 byte layout (`gridCols`/`gridRows` packed into one byte as two 4-bit nibbles, max 15 each) — a real issue caught mid-implementation, not planned up front — so `PARAMS_CODEC_VERSION` bumped to 3 (each field gets its own full byte); `decodeV1`/`decodeV2` stay registered for old links, `encodeV1`/`encodeV2` were removed as dead code once `encodeParams` moved to `encodeV3`. Verified visually via headless-Chrome screenshot (the new 14×14 default and an 18×18/80-node case both read as visibly less clustered than the old 10×8 default). See `CLAUDE.md`'s "Notes on M4.7.3" for the full scope-boundary reasoning.
- UI polish follow-up (no algorithm/codec version change): added a "⛶ Fit" button to the `Toolbar`, next to the zoom controls, that sets scale+pan directly from the current map's node bounding box (padded for label/shape overflow) so the whole map fits the visible canvas in one click instead of hunting for the right zoom level by hand.
- UI polish (post-M4.7.3, no algorithm/codec version change): four review/management fixes requested after using the running app. (1) Canvas wheel/trackpad zoom was scaling by a flat 12%/11% factor per wheel *event* regardless of scroll magnitude, which compounded into a runaway zoom on trackpads (many small-delta events per gesture) even though it felt fine on a notched mouse wheel — now scales by the actual (clamped) `deltaY`, plus the `Toolbar` gained explicit `−`/`100%`/`+` zoom controls for precise stepped control. (2) `generate()` used to always reuse `draftParams.seed` as-is, so clicking Generate repeatedly with no other changes silently produced the identical map — "click Randomize first" was a required, undocumented step. Reversed: Generate now draws a fresh random seed every click by default; a new `seedLocked` store field + "Lock current seed" checkbox is the explicit opt-out for holding a seed across regenerations while tuning other params. (3) The Region Preset dropdown was uncontrolled and always reset to a blank placeholder after any selection, so it could never show which preset (if any) was actually active — replaced with `selectMatchingRegionPresetId`, a store selector that epsilon-matches the current `biomeMix`/`wildernessWaterFraction` against the six registered presets each render, with a real "Custom mix" option (not a disabled placeholder) when nothing matches. (4) The address bar's `?map=` share code previously only got written after an explicit `generate()`/`loadMap()` call, so a plain page load restoring from localStorage (or the prototype default) left the bar without a working link — `writeShareCodeToUrl` now also runs once at module load, right after the initial map is resolved, verified via a dedicated test that stubs browser globals to prove it fires exactly once (no refresh loop) and correctly upgrades an old-codec-version share code to the current encoding. See `CLAUDE.md`'s "Notes on post-M4.7.3 UI polish" for full detail, including the test that had encoded the old (now-reversed) generate/seed behavior as correct and had to be rewritten.
- M4.8: radial (core-out) generation algorithm (**ALGORITHM_VERSION 2.2.0**, **PARAMS_CODEC_VERSION 4**) — a genuinely separate placement/edge-building algorithm, not a tweak to the grid one, selected via a new real `GenerationParams.placementAlgorithm: "grid" | "radial"` field (unlike every "preset" feature so far, which deliberately has no mode field). A core settlement sits at the exact grid center; up to 8 spokes (`radialSpokeCount`) grow outward as backbone chains; neighboring spokes get lateral ring connections whose likelihood tapers off with distance from the core (`radialCoreInterconnectivity` — the algorithm's defining trait, not a variant); a final convergence pass (`radialConvergenceRadius`) connects nodes from different spokes that ended up geometrically close. Three tunable flavor variants: `radialBranchChance` (organic spoke forks), `radialClusterChance` (small hamlet clusters — the "grouped settlements" knob), and `radialDeadEndPoiBias` (a true dead-end node, checked before the min-degree top-up runs, gets re-typed toward `poi` — "paths that lead nowhere tend to end at a point of interest"); a fourth considered variant (`waviness`) was deferred. New `core/generationShared.ts` extracts all geometry-agnostic classification/connection-type/connectivity-repair logic so the new `core/radialGenerator.ts` and the existing `core/generator.ts` share one implementation with no circular dependency between them (both depend on the shared module; neither depends on the other, since `generator.ts` must import `radialGenerator.ts` to dispatch to it). Radial derives its own grid size from node count + spoke count (`recommendedRadialGridDimensions`, `core/geometry.ts`) and `generateMap` stamps that derived size back onto the returned map's `params` — a real gap caught mid-implementation, since the validator's boundary-placement check and the share-code codec both key off `map.params.gridCols`/`gridRows`. `core/shareCode.ts` grew to codec v4 (28 bytes); `decodeV1`/`decodeV2`/`decodeV3` all backfill `placementAlgorithm: "grid"` (exact, not a guess) plus sensible radial defaults. `GeneratePanel.tsx` gained a "Generation style" selector that forks the Map Shape section (Grid cols/rows/Auto-size vs. a read-only derived-size line) and a new "Radial shape" slider section shown only for radial. Verified visually via headless-Chrome screenshot across multiple spoke counts, forced-on/off variants, and node counts up to 80 — clear central hub, visibly tapering interconnectivity, organic branch/cluster shapes, readable at scale. See `CLAUDE.md`'s "Notes on M4.8" for the clean-separation-across-layers reasoning and two bugs caught mid-implementation.
- M4.8 correction (**ALGORITHM_VERSION 2.3.0**, no codec change): the radial algorithm was reworked from literal fixed-radius spokes to organic, collision-aware maze-style growth, after direct user testing rejected the shipped version as "not shippable" — too literal, with straight rays out of the hub, no real direction freedom, and no genuine collision handling. Growth is now a **Growing Tree maze algorithm** (the well-known unification of recursive-backtracker/Prim's-style maze generation, found by researching maze algorithms at the user's suggestion) adapted to continuous compass-direction space: a frontier of growable nodes, each step picking a direction by **weighted random choice over every free direction**, biased only *against* pointing back toward the center — with deliberately **no term for "continue the previous heading,"** which was the original bug. Before committing a node, the candidate position is checked against nearby existing nodes: already-connected means try another heading; otherwise roll `radialCoreInterconnectivity` (still tapering with distance from the core, so the middle stays denser) to either join the corridor back into itself or reject and head elsewhere. `radialBranchChance` was re-pointed at the Growing Tree algorithm's actual defining knob — frontier-selection strategy (newest entry = twisty single threads with many dead ends; random entry = bushier, many more branch points) — after its first incarnation as a "grow another child immediately" burst measured as having no effect at all (redundant with the newest-first selection bias). Three bugs found while building it, each of which silently strangled growth or broke invariants: initial arms fanning out around the hub were being dropped as mutual "collisions" (adjacent 45°-apart directions at radius ~1 sit ~0.77 units apart, inside the 1.5 collision radius); hamlet cluster members blocked their own future growth the same way (fixed via a cluster-group exemption in collision detection, so high cluster chance no longer produces *fewer* nodes than low); and bucketing boundary-marker zones purely by *circular* radius let diagonal nodes clear the threshold while still sitting inside validator invariant 4's *square* forbidden band (fixed with the same explicit fx/fy box check the grid algorithm already used). Grid sizing also moved to area-based (from node count alone, arms no longer factoring in) after the arms-based formula over-sized the grid so badly the maze filled about a third of it. New regression test asserts the straight-through fraction at pass-through nodes stays near chance (~0.16) rather than near 1.0. See `CLAUDE.md`'s "Notes on the M4.8 radial-algorithm correction" for the full list of traps.
- M4.9: fine-tuning params (**PARAMS_CODEC_VERSION 5**, no ALGORITHM_VERSION change) — eleven behaviors that were hardcoded constants became adjustable params, each defaulting to exactly the value it was hardcoded to, so output is bit-identical unless a slider moves (the full suite, including both algorithms' determinism tests, passed unchanged after extraction). Six are radial-specific: `radialInwardWeight` (how hard paths avoid doubling back toward the core), `radialFalloffExponent` (how sharply interconnectivity decays toward the rim — the previously-fixed linear curve), `radialJitter` (positional irregularity), `radialRimFraction` (where the boundary-marked rim begins; the mid band's inner edge scales with it proportionally), `radialClusterMaxSize` and `radialClusterSpread` (hamlet size and tightness). Five apply under **both** placement algorithms, since they live in `core/generationShared.ts`'s geometry-agnostic taxonomy logic: `maxLargeSettlements` (was `MAX_CITY_OR_ABOVE`), `roadFraction` (was a fixed 50/50 road-vs-trail roll), `coastalChance` (was `INDEPENDENT_COASTAL_CHANCE`), `interiorBoundaryDamping` (was `MID_ZONE_BOUNDARY_DAMPING`), and `wildernessCheckMultiplier` (was a fixed ×0.2 on `checkRequiredFraction`). Threading params into `connectionTypeFor` also threaded them into `ensureMinimumDegree`/`repairConnectivity`. `GeneratePanel.tsx` gained a collapsible **Advanced tuning** section (radial-only knobs shown conditionally) so the main panel stays scannable. Each knob has a test proving a measurable effect, not just absence of crashes. See `CLAUDE.md`'s "Notes on M4.9" for the RNG-call-count trap that governs how these extractions must be written.
